一、根因与修复
--------------------------------------------------------------------------
【A】AI 援助「还是用不了」= 配的 model 是思考型
  · deepseek-flash / reasoner 这类是**思考型**：预算全花在 reasoning_content 上、
    content 为空；配真实盘面 prompt **首字实测 50s+** → 撞满 60s 硬超时。
  · 修复 src/game/aiaid.ts：
      - 新增 thinkingOffExtras(model)：对已知思考型模型名自动下发
        "thinking":{"type":"disabled"}
      - 新增 looksLikeThinkingModel(model)（设置面板 / 测试连接共用同一判定）
      - postChat 返回 sawReasoning；**空正文 + 有 reasoning 当场报错**（不再干等）
      - 上游 400 时去掉该字段重试一次（兼容不支持该参数的网关）
      - aiAidPing 回报 thinking:true/false
    src/main.ts：测试连接命中思考型 → 明确提示改 deepseek-chat

【B】「翻棋里第一排 / 最后一排 / 大本营的棋子走不动」= 复刻版多冻了 4 格
  · 原版走法生成是**两套子系统**，由规则结构体偏移 +1 的字节（game+0x4d，经 FUN_0002f684
    搬入 rule[1]）二选一：
      Path A  翻棋  Msg_Start_2(0x30a64) 置字节 0 → FUN_00068538 洗牌
                    生成器 FUN_0006919c，**没有大本营这道门 ⇒ 照走**
      Path B  布阵  Msg_Start_5(0x30b54) 置字节 1 → FUN_00069a74 读 .lay
                    生成器 FUN_0006a098，门闸 (&DAT_00133cb4)[i]==0 在 {1,3,56,58} 恒 1
                    ⇒ **整格跳过 ⇒ 子出不来**
    另 Msg_Start_3(0x38ce8) 的 `if (*(char*)(game+0x52)=='\0') FUN_00068538(...)`
    直接印证「规则字节 1 == 0 即翻棋」。
  · 与两份模式文案吻合：rulelay.txt 有「进入任何大本营的棋子不能再移动」，
    ruleflip.txt 通篇没有。
  · 修复 src/core/rules.ts：新增 baseFrozenOf(opts) = !opts.flipMode；
      canActivate: `if (isBase(from)) return false;`
                →  `if (isBase(from) && baseFrozenOf(opts)) return false;`
    ⇒ 翻棋可走出来、布阵/暗棋仍冻结（暗棋 flipMode=false，同布阵）。

⚠️ 附带澄清（差点误判成 bug）：
     翻棋里 **大本营与行营都是安全岛**（canLandOn: isCamp || (cmdSafeOf && isBase)，
     翻棋 cmdSafe=true），且翻棋开局 **50 格全被占满** ⇒ 一枚子站在底线格上时，邻居
     「吃不动（安全岛）/ 叠不上（己方）」—— **合法落点真的是 0，这是正确行为**。
     所以验这条 bug 必须用**净空盘**（第一版 UI 哨兵用满盘，4 格全 0，白折腾一轮）。
