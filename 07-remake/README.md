# 军棋 · 二人陆战棋（原版素材复刻版）

从 `com.cnvcs.junqi` v1.58 的逆向产物出发，用 **Vite + TypeScript + HTML5 Canvas**
重写的二人军棋。

核心取向：**画面不再"照着画"，而是直接用原版解包出来的位图** ——
棋盘就是原版 `board.png`（720×1071），棋子就是原版 `piece.png` 图集切片，
面板就是原版 `data/720x/ui/*.cfg` 记录的 9 宫格皮肤，音效是原版 `.wav`。
所以棋盘与棋子与原版**逐像素一致**，而不是"看起来像"。

原版规则与数据结构见 [`SPEC.md`](./SPEC.md)。

## 运行

```bash
cd 07-remake
npm install
npm run dev        # http://localhost:5180
```

其它脚本：

```bash
npm run typecheck  # tsc --noEmit
npm run test       # 核心逻辑自检（365 项）+ 中转的真实 socket 回归（35 项）
npm run build      # 产出 dist/
```

自带一个几何/交互自检开关：

```
http://localhost:5180/?probe=1
```

它会在页面里跑十六件事，并把结果写进 `<pre id="probeResult">`（配合
`chrome --headless --dump-dom` 就能当命令行断言用）：

1. `hitTest` `cellCenter` 是否严格互逆（点哪儿落在哪格）；
2. **在原版 `board.png` 自己的像素里**重新识别 46 兵站 + 10 行营，
   与 `ui/boardart.ts` 的 `COL_X / ROW_Y` 比对残差 —— 这是几何常量的回归哨兵；
3. 实走一步，确认规则层到渲染层链路通畅；
4. **翻棋布局**：50 枚棋子铺满非行营格、行营上 0 枚、全部盖着（绿色背面）；
5. **高亮框**：选中蓝框 `#0000ff` / 最后一步红框 `#ff0000` 的位置与像素量；
6. `vsai`：「人机对战」默认开局 = 翻棋·暗棋（模拟真点击后断言）；
7. `menu`：菜单 8 项同序；
8. `newgame`：「重新开始」弹新局对话框（4 行）；
9. `aidmenu`：人机态 ☰ 必须 9 格且第 9 =「AI 援助」；
10. `aidflip`：**翻棋**态 ☰ 也要 9 格、认得开局 50 张暗子、并真画一次建议框（数纯蓝像素 > 0）；
11. `selkeep`：真点一颗己方棋子 = **只是选中**，不许清掉 AI 建议；
12. `aidlabel` / `aidrelay`：等待中第 9 格必须写「取消 AI 援助」；出网必须走同源中转；
13. `basemove`：**规则层** —— 司令单放在底线两行 10 格（含 4 个大本营）上，
    翻棋·已翻开必须**走得动**、翻棋·盖着必须**走不动**（要先翻开）、布阵/暗棋·大本营必须**仍冻结**；
14. `basemoveui`：**UI 层** —— `cellCenter` 求格心 → `clickAt` **真鼠标链路**点 4 个大本营，
    必须**选中 4/4、画布蓝框 4/4**（旧版这 4 格全点不动）。
15. `flagwhy`：**扛不动旗时必须说话** —— 连长贴敌旗（敌雷已清）要说「只有工兵能扛」、
    工兵贴敌旗（敌剩 2 雷）要说「对方还有 2 颗地雷没挖完」，而**够不着的格子不许乱解释**。
16. `watch`：**AI 观战** —— 布局连走 12 手，要求**红蓝两边都真的动过**（旧 `aiTurn()`
    只认蓝方，红方那半回合会原地空转）、每一手都留下搜索深度/节点数；翻棋里数**中性绿背面**
    的像素验证**上帝视角**（关 → 满盘绿、开 → 掉到 2% 以下）；人的点击必须被拒；
    退出观战必须清掉定时器（否则会在首页上走一手）；
    指派成云端但没配 API 要**优雅暂停并退回引擎**；「逐」档走一手即停；学习面板真算出候选。
    另加六条（2026-09-15）：**缺省观战是暗棋且观者在"对局视角"**（`缺省暗棋=是(观者视角=对局)`）、
    **同一局面重复第 3 次判和**、**规避着法非空**（引擎据此降权）、
    **开局对话框每行文案都装得进 300px 的按钮**（超了会被静默裁掉两端，见踩坑 62）、
    **玩法行必须同时写着「布局」和「翻棋」**（`选翻棋=是`，只写当前值 ⇒ 用户以为没有翻棋，见踩坑 64）、
    **切到翻棋后「明暗棋」行仍在**（`·翻棋下仍可选视角`，旧版整行消失 ⇒ 翻棋没视角可选）。

### AI 援助怎么用

> ⚠️ 这是**复刻版自加**的功能，原版没有。它不替你下棋，只在你说不清该怎么走时，
> 让大模型**从规则引擎算好的合法着法里挑一条**，然后把那一步画在盘上。

一次性配置（存在浏览器 `localStorage`，只在本机）：

1. 进任意对局 → ☰ → **功能设置** → 底部「**AI 援助设置…**」；
2. 填三样必填：**接口地址**（任何 OpenAI 兼容端点，如 `https://api.deepseek.com`，
   后缀 `/v1/chat/completions` 会自动补齐）、**API Key**、**模型名**（如 `deepseek-chat`）；
3. **先点「测试连接」** —— 1 秒内给出结论，不必等对局里转一分钟才发现 Key 填错。
   看到「连接成功：16ms · deepseek-chat」才算通；报错文案会直接说是哪一环：
   - `模型接口返回 401：Authentication Fails…` ⇒ Key 不对；
   - `模型接口返回 404` ⇒ 模型名或接口地址不对；
   - `中转失败：上游 60 秒没有响应` ⇒ 地址本身连不上（见下面"上游代理"）；
   - `连不上模型接口：…` ⇒ 网络/DNS 问题。
4. 另外两格可留空：**超时（秒）**（默认 60；推理型模型如 `deepseek-reasoner` 建议 120）、
   **上游代理**（如 `http://127.0.0.1:7897`，只有走中转时才生效）。
5. 点「保存」，按钮会标「（已配置）」。

日常使用（**布局对战**和**翻棋暗棋**都有，布阵没有）：

1. 首页点「**人机对战**」——原版行为是直接开一局**翻棋·暗棋**；
   （想打布局对战：首页点「两人对战」→ ☰ 功能设置 → 把「人机对战」切成「开」。）
2. **等约 2.5s 的「战斗开始」横幅走完**（横幅期间右上角 ☰ / ↻ 浮标是隐藏的）；
3. 点右上角 **☰** → 点第 9 格「**AI 援助**」；
4. 顶部提示条会**一直显示进度**：`正在问模型…（已等 Ns，最多 60s，再点一次可取消）`，
   秒数每秒在涨 —— 所以"它到底有没有在跑"是**看得见**的；
5. 等约 1–2s，提示条变成建议，例如
   - 布局对战：`AI 建议：排长 格5 → 格11（…）`
   - 翻棋：`AI 建议：翻开 格12 这张暗子（点一下即可）（…）`
   同时棋盘上会出现**蓝框**（翻棋里翻子时起点=终点，所以是一个框）标出该点哪；
6. 照做即可：布局对战点**起点格再点落点格**；翻棋点**那一格**就翻开了。

**想中止**：等待时再开 ☰，第 9 格这时写的就是「**取消 AI 援助**」，点它即可 ——
取消**立刻生效**，不用等对面回应。任何一步棋走完，建议框自动消失。

没配置就点它会直接把你带到设置面板；配置不全时提示条会说明差哪一项。

### AI 观战怎么用（两台电脑自己下，你负责看）

> ⚠️ 同样是**复刻版自加**的功能 —— 原版只有"人打电脑"，没有"电脑打电脑"。
>
> 它的用途是**学棋**：两台 AI 自动对弈，你坐在旁边看整盘棋、看它每一步在想什么。

**两侧执子者可以分别指派**，这是这个模式最关键的开关：

| 指派 | 看到的是什么 |
|---|---|
| 引擎 × 引擎 | 本地 native 规则引擎（negamax）**自己打自己**，靠等级拉开强弱 |
| **云端 × 引擎** | 云端大模型对本地规则引擎 —— "AI 对战规则 AI"，两种思路正面碰 |
| **云端 × 云端** | 两边都是大模型，看模型自己怎么理解这盘棋 |

- **引擎**：本地规则引擎，5 档（新手 / 容易 / 普通 / 高级 / 困难）。
- **云端**：走「AI 援助」那条同一条管线 —— **合法候选由本地规则层算好，模型只挑一条 + 说理由**。
  所以云端棋手**不可能走出非法着法**；棋谱里记的是"想了多久 + 为什么"（不是搜索深度），
  理由会显示在棋谱行末。
- ☰ →「**指派棋手**」里点红方 / 蓝方那一行即可循环切换：
  `新手 → 容易 → 普通 → 高级 → 困难 → 云端 → 新手`。
- ⚠️ 云端棋手**要先在「功能设置」里配好接口地址 / API Key / 模型名**（跟 AI 援助同一套配置）。
  没配就轮到它时，观战会**暂停并把原因常驻在解说条上**、自动退回本地引擎（不会卡在"思考中"），
  按「继续」就能接着下。

1. 首页右下角点「**AI 观战**」（钉在「四国军棋」正上方）—— 会先弹一张**开局表**：
   **玩法** · **明暗棋** · **红方** · **蓝方**，选完点「确定」开局。上次怎么开的会记住，下次沿用。
   ★ 玩法那一行写的是 **`布局 → 翻棋`** —— 读作"现在是布局，点一下变翻棋"：
   **两个玩法都写在按钮上**。别小看这点 —— 只显示当前值时，用户整屏找不到"翻棋"三个字，
   会直接判定"AI 对战做不了翻棋"（实测反馈原话就是「**AI 对战增加翻棋**」）。
   **缺省是`布局 · 暗棋`** —— 见下面「明棋 / 暗棋」。
2. 开局即全自动：每手之间停 **2.6 秒**（"慢"档 —— 观战是拿来学棋的，默认就慢）。
   标题栏**左侧解说条**实时显示 `观战 · 第 N 手` +
   `谁·谁在执子 走了哪一步 ▲/▼分差` + `深度 / 节点 / 耗时`（云端手则是"云端决策 xx ms + 理由"）。

#### 明棋 / 暗棋 —— 缺省是**暗棋**，而且你真的看得出来

| 选 | AI 知道多少 | 你**第一时间**看到什么 |
|---|---|---|
| **暗棋**（缺省） | 看不到对方的子，靠 `buildBelief` 推理 | **未翻开的子就是背面**（对局视角）；视角跟着行动方走，红蓝各半盘轮流亮 |
| **明棋** | 全知（`revealAll`），双方盘面全亮 | 满盘都亮，与"上帝视角"画面一致 |

★ 关键点：**选了暗棋，观者的上帝视角会自动关掉**（`enterWatch` 里 `watchGod = watchReveal`）。
不这么做的话，上帝视角一开就把暗棋**抹平**了 —— 两种模式画出来一模一样，
你会以为"我明明选了暗棋，怎么还是明棋"。想偷看全貌，自己按 ☰ →「视角·开」。
（每开新局都按当次选的明暗棋重置一次视角，这是刻意的。）

**翻棋的「明暗棋」这一行**：翻棋规则层**恒为暗**（盖着的子连 AI 都不知道，只能靠推理），
所以那一行只决定**你**看到什么 —— `明棋：全知`（盘面全亮，看着方便）/
`暗棋：对局`（跟棋手一样，只看得见翻开过的）。翻棋观战**缺省全知**
（学棋的价值就在看得见全貌）；想体验"信息不全"就点成「暗棋：对局」。
旧版翻棋下这行整行不显示，等于翻棋观战连视角都没得选。

**想看"AI 在不知道暗子是什么时怎么下"** = 就用缺省的**暗棋**开局：
盘面上未翻开的子就是背面，AI 同样看不到 —— 而你随时可以 ☰ →「视角·开」把全貌摊开，
对照"它猜的"和"实际是什么"。
⚠️ 上帝视角**只改显示**，`flip.opts` / `lay.opts` 一行没动 —— 观战**不给 AI 开天眼**
（**云端棋手也一样**：它拿到的盘面描述和本地引擎的知情权完全相同），
否则学到的就不是这套 AI 的棋了。

#### 两台 AI"谁都不过谁"怎么办？—— 防磨棋两层保险

两台同水平的 AI 最爱在两三个格之间**无限来回**（子力毫无变化，谁都占不到便宜）。
原版只有"连续 70 步无吃子"这一条，要磨很久才收得住，观战看起来**像死机**。所以：

1. **事前引导**：观战侧记着出现过的局面指纹，把"走完会回到旧局面"的着法**沉到候选队尾**
   （只降权、不剔除），让它优先换个下法。
2. **事后兜底**：**同一局面重复 3 次判和**（`DRAW_REPETITION`）。
   ⚠️ 这条是复刻版自加的，**人机 / 双人对局不生效**（`repeatDraw` 缺省 0），
   保持原版行为；只有观战会打开它。
3. 原有的"连续 70 步无吃子 / 累计 1000 步"照旧兜底。

判和时解说条会写明原因（"同一局面重复 3 次（双方都不肯变着）"），不会让你猜为什么停住了。

**顶栏右侧四键**：`✓` 暂停/继续 · `↻` 走一手 · `📊` 棋谱 · `✗` 退出观战。
棋盘上那两枚浮动图标里**右侧一枚**在观战时会变成「暂停 / 继续」（平时是"悔棋"）——
观战悔棋等于替 AI 改棋，`doUndo()` 里另有保险丝会明确拒绝。
⚠️ 这枚键**复刻版自定的语义是"悔棋"**，而原版里同位置的蓝箭头其实是**返回主菜单**
（真正的悔棋在 ☰ 里）—— 已记录为待对齐分歧，见踩坑 69。

#### 右侧「学习面板」——把"它为什么这么走"摆出来

> 用户原话：「走棋走得太快，我都来不及看他的思路」。于是观战有两件配套的事：
> **慢下来**（下面的速度档，尤其是「逐」档）+ 把思路摆在一块**不会自己消失**的地方。

面板挂在棋盘**外侧的留白**上（`position: fixed` 贴右；`#app` 宽度 = 棋盘宽 ⇒
单侧留白就是面板的可用宽度），所以**不压棋盘**。留白不足 168px（手机竖屏）时自动收起 ——
宁可没有面板，也不能糊在棋子上挡着看棋。

面板分四块：

| 块 | 内容 |
|---|---|
| 本手 | 第几手 · 谁（红/蓝）· 什么水平 · 走了哪步 · `搜索 N 层 / M 节点 / X ms` · **走后的局面分**与这一手的赚亏 |
| 候选榜 | **它从多少种走法里挑出哪几条来掂量**，每条走完的局面分，并高亮**实际落子的那条** |
| 名次说明 | 实际落子那条在**两把尺子**上的顺位（见下） |
| 最近 6 手 | 滚动棋谱，不用开对话框 |

**候选榜是"看思路"的核心**，但它有**两把尺子**，面板会把两个顺位都报出来：

- **搜索前顺位** = 引擎根节点的启发式排序（`aiRootOrder`）——**吃子一律优先**（`+100000`）。
- **走后局面分** = 走完这一手之后的静态估值（`evalForSide`，与棋谱 / 解说条同一把尺子）。

所以你会经常看到「搜索前第 1 顺位 · 走后局面分第 5 名」——**这不是它走错了**：
吃子优先让"师长吃连长"一上来就排第一，而静态账只算「这手值多少」，
算不出一手之后的还击。真正的取舍发生在搜索里，面板上看不出来 —— 那正是棋力所在。

⚠️ 候选榜只对**布局的引擎手**有意义：翻棋的一手是"翻开某张暗子"（没有走完后的局面分可谈），
云端手没有"搜索过程"（它的思路就是模型给的那句理由）。

**☰ 里还有**：

| 项 | 作用 |
|---|---|
| `视角·开/关` | **上帝视角**。关掉 = 只剩"对局视角"，没翻开的子看不见 |
| `速度·逐/慢/中/快/极` | 每手之间的停顿（**逐** = 走一手停一手 / 2.6s / 1.3s / 0.55s / 0.13s）—— 云端手另加网络往返时间 |
| `面板·开/关` | 右侧学习面板（屏幕太窄时它会自动收起，这里也能手动关） |
| `指派棋手` | 红 / 蓝**各自**由谁执子：引擎 6 档，或**云端**（见上表） |
| `换个玩法` | 弹出与首页同一张**开局表**（玩法 / 明暗棋 / 红蓝棋手），顺手也能改两边指派 |

★ **「逐」档是学棋最舒服的档**：走完一手自动停住，你看够面板再按「走一手」/「继续」走下一手。
固定间隔再长，也会在你低头看面板时偷偷走掉两手 —— 逐手档里「继续」的语义就是
"再走一手，然后接着停"。

**棋谱面板**（`📊`）里每一手都带 `深度 / 节点数 / 耗时 / 分差`。分差是**引擎自己的
估值函数**算的（与 AI 决策用的同一把尺子，不另起一套），绿线 `▲` = 这手赚了、
黄线 `▼` = 亏了。云端手没有"搜多深"，改报**耗时 + 模型给的理由**。
点「**复制棋谱**」能把整局贴到别处继续研究。

命令行直通：`?watch=1`，可加 `&wmode=flip`、`&wlv=4,2`、`&wk=cloud,engine`、`&wsp=逐`、`&wpause=1`、`&wshow=0`、`&wstudy=0`。
（`wlv` 只管"本地引擎"那一侧；`wk` 指派执子者，`cloud` / `engine` 各一侧；
`wsp` 认档位名（逐/慢/中/快/极）；`wshow=0` 强制暗棋（缺省已是暗棋，自检用来显式压回）；
`wstudy=0` 收起右侧学习面板。`&wpause=1` 起手就暂停 —— 逐手采样时用它避开自动走子。）

### 出网方式：为什么默认走「本地中转」

浏览器**直接**请求模型接口有两个死穴，第二个是 2026-09-14 玩家实报「AI 援助超时」的根因：

1. **跨域**：页面在 `127.0.0.1:5180`，接口在别家域名。带 `authorization` 的 POST 必先发
   `OPTIONS` 预检，接口方不回预检头就什么都发不出去。
2. **用不了本机代理**（★）：Chrome 默认只认 **Windows 系统代理**，你在设置里填的
   `http://127.0.0.1:7897` 它根本不看。实测本机 `api.openai.com` **直连挂死 >9 秒**，
   而走 `7897` 只要 **1.1 秒** —— 症状就是"点了 AI 援助一直转，然后超时"。

所以 `vite` / `vite preview` 会挂一个**同源**中转 `/__aiaid/relay`
（实现：**`server/aidrelay.ts`** —— 2026-09-15 从 `vite.config.ts` 里搬出来的，
因为它需要被 `npm test` import 起来跑真实网络回归），由 Node 侧代发请求：
同源没有跨域，Node 侧能显式走 `x-aiaid-proxy`（HTTP `CONNECT` 隧道）。
页面启动时会探一次 `/__aiaid/ping`，**在就默认走中转**；
`npm run build` 后挂在纯静态服务器上没有中转，会自动**退回直连**（那条路对
DeepSeek / 智谱 / 通义 / moonshot / 硅基流动这些本身开放跨域的接口照样能用）。

**中转自己会扛抖动**（2026-09-15，玩家实报 `中转失败：read ECONNRESET`）：

- **不复用连接**：Node 19 起默认 agent 开着 keep-alive，池里的 socket 被上游回收后
  再复用就是半开连接（`read ECONNRESET` 的典型来源）。中转一律 `agent: false`
  + `Connection: close`，用完即关；
- **瞬态失败换新连接重试**，最多 3 次（第一次 + 2 次重试，每次间隔 220/440ms）；
  重试期间总超时预算不变。**只重试链路抖动**，超时 / Key 错 / 模型答得不对一律不重试
  （判定表 = `src/game/neterr.ts`，浏览器与 Node 共用同一把尺子）；
- 响应头 `x-aiaid-attempts` 如实报出这一发打了几次（成功和失败都带）——
  页面据此决定还要不要再叠一层重试，避免两边各退一步互相抵消（踩坑 66）。

**报错要能"指路"，不能只回一句"连不上上游"**（2026-09-15，玩家第二次实报
「应该还是不能用啊，一直提示连接不上上游」——见踩坑 67）：

- **连接阶段单独计时**：8 秒内连不上（DNS / TCP / TLS）就**立刻点名 host**
  （`连不上上游 api.openai.com:443：connect ETIMEDOUT`），不再伪装成"上游 60 秒没回应"。
  可用 `AID_CONNECT_TIMEOUT_MS` 覆盖（测试用 300ms 验它真的会立刻报）。
- **直连不通自动借本机代理**：第一次直连失败、且目标是外部域名时，探测本机
  7897 / 7890 / 10809 / 10808 / 1080 / 8889，有活着的就借它再打一发，并在
  `x-aiaid-proxy-used` 头里**如实回报**（UI 写"已自动走本机代理 X"）。
  ⚠️ **本机地址除外**（`127.0.0.1` / `localhost` / `::1`）—— 那是"服务没起"，
  借代理只会把 `ECONNREFUSED` 糊成代理的 502。测试里用
  `setLocalProxyCandidates([])` 或 `AID_LOCAL_PROXIES=` 关掉它，免得开发机的 Clash 让结果漂移。
- **`GET /__aiaid/diag`**：逐段量 DNS → TCP → HTTPS → 代理，回一句**结论**（`verdict`）。
  设置面板的「**诊断出网**」按钮就是它的入口 —— 点一下告诉你到底哪一段断了、该改哪一格，
  而不是让你对着"连不上上游"反复瞎试。
- **502 分两种**：中继自己造的 502 带 `x-aiaid-origin: relay`，页面只把这一种报成
  「中转失败」；上游网关的 502 原样透传，不再让你去查本地中转。

设置里的「**中转·自动**」可手动改成「**中转·强制**」/「**中转·关闭**」；
说明框会如实写出「当前中转=开/关」。

> ⚠️ 中转**只监听 127.0.0.1 且要求自定义头 `x-aiaid-url`**（别家网页带自定义头的请求
> 会先被浏览器拦在预检那一步）。它只为本机开发服务，**不要**把 dev server 暴露到公网。

**排查"点了没反应"**：
- **分不清是哪一种病 ⇒ 先点设置里的「诊断出网」**（2026-09-15 起）。它逐段量
  DNS / TCP / HTTPS / 代理，直接把**结论**写在说明框里（"连不上 X：端口不通"、
  "本机有代理 7897 活着，这个地址需要走代理"、"上游能直连，问题在 Key / 模型名"…）。
  对着"连不上上游"反复瞎试之前，先点它一下。
- 提示条停在"正在问模型…"且秒数在涨 ⇒ 请求已发出，是**对面没回**，到点会自动报超时；
- 立刻显示"连不上模型接口" ⇒ 地址/网络不通；显示 `模型接口返回 4xx` ⇒ Key / 模型名不对；
- 显示 `中转失败：…` ⇒ 中转取不到上游（地址不通 / 代理没起 / 代理地址填错）。
  2026-09-15 起会带上重试次数与根因，例如
  `中转失败：连不上上游：read ECONNRESET（已重试 3 次）`、
  `中转失败：上游代理拒绝转发：HTTP/1.1 403 Forbidden`（**后者不重试**：代理拒绝是配置问题）；
- 显示"已取消 AI 援助" ⇒ 你在等待期间又点了一次（那一格此时就是"取消"）。

> **国内直连类接口（DeepSeek / 通义 / 智谱 / Kimi / 硅基流动）不需要代理。**
> 2026-09-14 实测本机：Windows 系统代理是关的，浏览器直连 DeepSeek 的 CORS 预检 200（0.26s）、
> POST 401（0.12s），走中转同样 401 —— **两条路都通**。所以这类地址若还超时，
> **几乎一定不是网络**，而是下面这两种：
> ① **模型名填成了 `deepseek-reasoner`**（推理型，思考动辄几十秒）→ 军棋只要挑一步，
>    换回 `deepseek-chat`；
> ② **页面还是旧构建**（改过 `vite.config.ts` 后**必须重启 dev server**，否则中转插件不存在）。
> 拿不准就先点设置里的「**测试连接**」：`连接成功：1234ms` 就是通的；
> 秒数特别大（>30s）才说明上游真的慢。

```
│   └── aiaid.ts          AI 援助（自加）：局面 → prompt → 候选编号回填为合法着法
├── main.ts               事件编排（不写规则）+ `?probe=1` / `?ai=N` 自检

└── aidrelay.ts           AI 援助的**同源中转** `/__aiaid/*`：Node 代发 + 换新连接重试 + 断开作废

```

**分层原则**：`core` 不碰 DOM，`ui` 不碰规则，`ai` 只吃 `Position` 吐着法，`main` 只做"事件 → 控制器 → 重绘"。
因此加 AI 或联网时，只需替换"谁来驱动 `click()`"，规则与渲染完全复用 ——
`ai.ts` 就是照这个约定接进来的：它不 import 任何渲染代码，只调用 `rules.ts` 的走法生成与吃子判定。

## 几个容易踩的点

1. **图集是 4×7，不是 4×6**。第 7 行是空白面；行数写错会让棋子纵向累积偏移、
   每枚都带出下一行的字（这个 bug 实际发生过）。
2. **图集单元之间没有分隔线**。`344×427 = 4×86 × 7×61` 严丝合缝，
   切片就是 86×61，**不要内缩**（曾误以为有 4px 分隔线而裁掉一角）。
3. **这些 9 宫格皮肤的中段只有 1px**（如 `btn.png` 24×90 切成 44/45）。
   元素被压扁到比"上切片+下切片"还扁时，中段退化成 0 高，
   面板底色会从中间漏出来，表现为一条白缝。做法是给元素**定高**
   为 `(上切片 + 下切片) × scale + 2px`，只让中段横向拉伸。
4. **`rule*.txt` 是 GBK**，抽取时统一转 UTF-8；否则一读就是"鏂囦欢"。
5. **`public/assets/` 是游戏素材，`build.assetsDir` 必须改名**（本工程设为 `bundle`），
   否则 Vite 打包产物会和原版素材混进同一个 `dist/assets/`。
6. **列 2 不是纵向铁路**。列 0/4 才是；列 2 只在两方交界处有一小段跨越。
7. **`.lay` 行序与棋盘行号相反**（红方 `boardRow = 5 - layRow`，蓝方 `boardRow = 6 + layRow`）。
8. **中缝是 3.508 倍行距**（`datax#156` 实测 248px），不是 3.3；备用棋盘 `#250` 才是 207.6px
   —— 两张棋盘别混用，混了上半盘会整体偏高 52px。
9. **翻棋背面是绿色，不是黑色**。图集 `r6c0` = RGB `112,156,0`；
   黑色（`r6c3`）在翻棋里**根本没用**。这个按"想当然"实现过一版黑背面，被实拍推翻。
10. **原版没有落点预览**。选中只画纯蓝 `#0000ff` 框，最后一步在起点+终点各画一个纯红 `#ff0000` 框。
    用半透明方块"提示可走位置"是不像原版的根本原因。
11. **翻棋只铺 50 格**：棋盘 60 格 − 10 行营。铺 60 格会越界取到 `undefined` 并霸占行营。
12. 测试脚本要用**系统 Node**（或 `--experimental-transform-types`），
    托管 Node 的 strip-only 模式不支持 `enum`。
13. **沙箱里 `rm -rf` / `shutil.rmtree` / `vite build` 的清目录会被 safe-delete 拦截**。
    解法：抽取脚本改成逐文件 `os.remove`；重建 `dist/` 前先用 Python 手动清空再 `vite build`。
14. **Ghidra 镜像基址 = `0x10000`，不是 0**。地址 `0x15xxxx` 对应的文件 vaddr 是 `0x14xxxx`，
    而且进 `.data.rel.ro` / `.data` 还要再平移一次。按 1:1 读文件会读到垃圾 ——
    这就是第一轮"AI 没有可读常量表"的误判根源。
15. **无头 Chrome 的 `--virtual-time-budget` 会冻结 `Date.now()`**（JS 同步执行期间时钟不走）。
    凡是用墙钟做"超时收手"的逻辑，在无头里都会跑飞；必须再加一道节点数/迭代数硬闸门。
16. **Chrome 子进程写不了工作区文件**（`Failed to write file: 拒绝访问`）。
    截图别用 `--screenshot=`，走 CDP 把 base64 交回 Node 落盘（`tools/shot.mjs`）。
17. **连线关系必须查 native 表，不能"看图"**。底图上的斜线是**行营的进出线**，
    不是全图 8 邻接。按 8 邻域实现会多出 **32 条斜走**（如 `(1,1)→(2,0)`）。
    真相：全邻接表 fileoff `0x122ae0`（133 边，只有行营是 8 度）、
    走法步进表 fileoff `0x123350`（98 边 = 全邻接 − 35 条铁–铁边）。
    验证器 `tools/_bench/moveequiv.ts`（2160 组比对，须为 0 不一致）。
18. **"撞强子"和"非工兵碰地雷"在原版里不是"会死"，而是"压根不能选"**。
    原版在落点生成阶段就挡掉（`FUN_00068b38`）：目标更强 → 直接不成落点；
    地雷 → 仅工兵（炸弹另有"双方消失"规则）。`rulelay.txt` 的字面描述与引擎行为不一致，
    **以引擎为准**。
19. **中缝只有列 2 能纵向穿过**（`27↔32`）。原版对格 `26/28` 禁下行、`31/33` 禁上行，
    列 1/3 因此完全断开 —— 铁路标志位表在 fileoff `0x123bc4`（32 格，含行 `5/6` 全宽）。
20. **调页面必须按「几何 → 字号 → 纵向 → 字体 → 样式细节」的顺序，不能跳。**
    踩过的坑：先去抠原版字体、量笔画粗细，量到"雅黑只比原版重 6%"，于是断定"雅黑够用"；
    可当时文字整体还低了 2~4 设备px —— **纵向错位被误算进了"字体差"**。
    等把纵向对齐之后重比，雅黑 20.65 / 原版自带 MYingHei **12.14**，差了一倍。
    几何没锁死之前去比字体、比阴影，得到的全是错结论。
21. **原版字体是从 APK 里抠出来内嵌的，不是系统字**。`assets/_unresolved/data/*.ttf`
    按 SFNT `name` 表读出真名才是 `MYingHeiGB18030C-Bold` / `Arial` / `ZYKai_FRIZQT`，
    文件名是内容哈希、完全看不出是什么。可用 `tools/_audit/fonts.mjs`
    让 Chrome 自报"实际用了哪支"（computed `fontFamily` 只反映候选串，不反映真身）。
22. **`--ds` 是 1.25 缩放时的亚像素单位**：`calc(Npx * var(--ds))` 里的 N 是 **art px**。
    改字号/偏移时别用全表 `sed`（见 README 上文的警告），改成变量再扫。
23. **原版整帧是「720×1280 设计稿 ×1.25 双线性放大」**，不是 900×1600 原生渲染。
    所以**文字必须走位图**（`textbmp.ts`）：DOM 文本会被 Chrome 按设备尺寸重新光栅化，
    笔画更硬更粗（柔和度 1.35 对原版 3.04）。`transform: scale()` 救不了，
    亚像素 `blur()` 会被量化成 0 —— 只有位图不会被重新光栅化。
24. **九宫格面板的绝对定位子元素会整体偏移**。`border-image` 会内缩 padding box
    （`dlg.cfg` 缩 83/8/8/8 art），而原版 XML 的 `rect` 是相对**整个框**的。
    内容必须包一层按 `--bt/--br/--bb/--bl` 反向偏回的 wrapper（`.dlg-inner`），
    否则会偏出 ~82 设计 px。按钮里的文字位图同理。
25. **原版对话框既不压暗背景、按钮字也不是米黄**。加 `rgba(...,.42)` 遮罩和用
    `#fff6da` 都是"想当然"；实拍差分证明对话框外棋盘**逐像素不变**，按钮字是**纯白 `#ffffff`**。
    对标定类结论，永远以「同局两次截屏差分 / 像素取样」为准，别沿用前一个界面的取值。
26. **用"平移搜索"判断"是不是偏了"有两个坑**（本项目踩过，见 SPEC §9.8.6）：
    ① 图块里若有**高对比度的非文字元素**（面板边框、图标），权重会盖过文字，
       最优解反映的是那些元素 —— 取块时要内缩避开（`dlg_shift.py` 的 `INSET_X`）。
    ② 把最优解**应用一次后重跑估计器**。若最优解跟着一起漂（−1 变 −2），
       说明不是位置问题而是**光栅化相位/字形差**，再平移只会越弄越糟。
       实据：照"文字偏右 1px"改，全图差 8.04 → **9.01**，反而变差。
27. **并排/差分比对之前，先确认两边是同一个状态**。半透明面板、有状态切换的界面，
   状态不一致会被伪装成"渲染差"。实据：实拍里「玩法」是**翻棋**，`#btnOne` 默认走**布局**，
   于是那一行是**内容不同**；再加上面板半透明、底下棋盘也不同，
   量出来的"差"是 **8.04**，而把状态对齐后真实值是 **6.08**（面板空白区 2.48 → 0.37）。
   **先对齐状态，再谈像素。**（★ 那条"默认走布局"本身就是 bug，2026-09-13 已修，见 §9.9）
28. **判定"这格到底写的什么字"别靠肉眼**：把**候选值各截一张**，分别与实拍同一矩形比残差，
   小者胜。**同文本残差基线 ≈ 6.6~7.3**（用等值行量出来的），超过它一倍就只可能是"字不一样"。
   实据：原版「玩法」= 翻棋（翻棋候选 7.76 vs 布局候选 11.78）。
29. **`floatButton()` 造的新按钮会丢掉占位元素的 `id`**。`index.html` 里是
   `<button id="floatMenu">`，`replaceWith` 换掉之后 `#floatMenu` 就选不中了 ——
   所有靠 id 定位的自动化脚本会一起 MISS（现象是 `#floatMenu -> MISS` 但页面看起来正常）。
   在 `buildFloats()` 里显式 `floatMenu.id = "floatMenu"` 补回。
30. **沙箱里 `(cmd &)` 起的后台服务会随该条 shell 退出而死**。后续命令拿到的是
   "连接被拒/代理 502"，页面自然是空白 —— 表现成 `#btnOne -> MISS`、`mode` 为空，
   极易误判成"代码坏了"。服务要用工具的后台模式起；查本地端口要 `curl --noproxy '*'`。
31. **回归哨兵要"故意把 bug 放回去"验一次**。只加断言不验证断言，等于没加。
   本项目实测：把 `setMode("flip")` 改回 `"lay"` 后 `npm run probe` → `EXIT_CODE=1`
   并指名缺陷；改回来 → 全绿。**哨兵本身也是要验收的产物。**
   ⚠️ 还要多验一步：**确认 `probe.mjs` 的 `fails` 列表里真有这条**。页面里的哨兵
   （`src/main.ts` 的 selfCheck）和命令行断言（`probe.mjs`）是**两处**，只加了前者、
   忘了后者时，哨兵行会打印 `✗` 但退出码仍是 0、末尾还照样写"✓ 自检通过"
   —— 比"没有哨兵"更危险，因为它给人一种有保护的错觉。本项目 2026-09-14 真踩过
   （`aidflip` 的 `蓝框px=0 ✗` 而 probe exit 0）。现在 `probe.mjs` 末尾有一条
   **通用兜底：任何哨兵行含 `✗` 一律判失败**，新增哨兵不改断言也不会漏判。
32. **页面调第三方接口 = 必须过 CORS 预检**，本地假端点也不例外。页面在 `127.0.0.1:5180`、
   桩在 `127.0.0.1:8790`，跨源 + `authorization` 头 ⇒ 浏览器先发 `OPTIONS`；桩不回
   `access-control-allow-*` 时表现为 **`TypeError: Failed to fetch`**，极易误判成"接口地址填错了"
   或"按钮没接上"（`runAiAid` 的 toast 只说"连不上模型接口"）。桩必须处理 `OPTIONS` 并回
   ACAO/允许头（`aidstub.mjs` 已补）。**真服务都带这些头，桩不带就测不出真链路。**
33. **PowerShell 里 `Start-Process` 起的长驻服务会随该次会话被回收**。比 `(cmd &)` 更隐蔽：
   起完 900ms 后 `Get-NetTCPConnection` 明明还看得到监听，等真正跑测试时进程已经没了
   （实测：桩先有监听、再"连接被拒"，一轮 E2E 白跑）。长驻服务一律用**工具的后台任务方式**起；
   `taskkill`/`Stop-Process` 之后**必须重新确认端口**再跑测试。
34. **"只是选中一颗子" ≠ "局面变了"**。`LayGame.click()` 对**选中**也返回 `true`，
   于是"点一下棋盘就 `afterTurn()`"这种写法会顺手 `clearAid()` + `status(最后一条日志)`，
   结果是玩家点了「AI 援助」再点它建议的那颗子 ⇒ **提示当场消失**，toast 还**倒退**成上一局的
   旧消息（实测"AI 建议：…"变回"新对局开始，红方先行"）。
   判据要用 `takeMoveSpec() !== null || messages.length 变了`，不是 `click()` 的返回值。
   `afterTurn(msgs, spec, silent)` 的第三个参数就是干这个的，`probe` 里 `selkeep` 守着它。
35. **功能做了 ≠ 用户找得到**。「AI 援助」的入口曾在代码里挂 `mode === "lay"`，
   而主菜单「人机对战」按原版行为进的是**翻棋·暗棋** —— 于是用户点完最显眼的那个按钮，
   翻遍菜单也找不到功能（2026-09-14 实报"我要怎么调出 ai 援助啊"）。
   教训：**入口的可见条件要按"用户从哪儿进来"推，不是按"我在哪个模式实现的"**。
   `probe` 的 `aidflip` 现在同时守 `aidmenu`（布局）与翻棋两条入口。
36. **`draw()` 有多个模式分支时，新增的渲染参数要每个分支都加**（典型是漏一个 `return` 前的分支）。
   翻棋的 `paint({...})` 曾漏传 `aidPair` ⇒ 提示条写着"翻开 格0"，棋盘上却**一个框都没有**，
   toast 还会在 2.6s 后消失，玩家等于什么也没看到。**判据不是"代码里赋值了"，而是"画布上真有像素"**：
   `aidflip` 哨兵现在真 `draw()` 一次并数纯蓝像素（> 0 才算过）。
37. **`fetch()` 的 resolve 只代表"响应头到了"，不代表 body 到了** —— 超时与取消必须覆盖到
   **读 body 结束**。本项目真踩过（玩家实报"一直显示正在问、再点只说取消了上一次"）：
   把 `clearTimeout` / `signal.removeEventListener` 放在 fetch 之后的 `finally` 里，
   于是**响应头一到，超时定时器被清掉、取消信号也断开了**，接下来的 `res.json()`
   变成**永久挂起且无法取消**；`aidBusy` 再也回不到 false，玩家之后每次点只会看到"已取消"。
   "先回 200 头、再慢慢吐 body"的网关/代理最容易命中。正确写法：`fetch` 与读 body 放**同一个 try**，
   清理只在最外层 `finally`。守它的测试是 `tests/run.ts` §19 ⑥（忠实地让读 body 跟着 signal 一起作废）。
38. **UI 上的"取消/中止"不能只发信号就完事**。即使底层 promise 因为对面的问题永不 settle，
   界面也**必须立刻**回到可用状态，否则一次坏请求就永久锁死功能。做法是加一个"代次"（`aidSeq`）：
   取消时 `++aidSeq` 并复位 `busy`，在途回调回来后发现"自己不是最新一代"就**直接返回、不碰界面**。
   否则被取消的那条 late reject 还会去 `status(...)`，把玩家刚看到的新提示打回旧文案。
39. **让标签如实反映"点下去会发生什么"**。等待中 ☰ 第 9 格本来还写「AI 援助」（点下去其实是取消），
   玩家的原话就是"为什么点它一直显示取消上一次" —— 功能没错，是**标签骗人**。
   同一个位置在不同状态下做不同的事，就必须在不同状态下显示不同的字。
40. **`status()` 的 toast 有 2.6s 自动隐藏，不适合表示"还在进行中"**。一次性的"正在问模型…"
   不到 3 秒就没了，玩家根本不知道它是否还在跑（"我怎么知道他有没有"就是这么来的）。
   做法是**每 500ms 重发同一条**（附带"已等 Ns / 最多 60s"），既常驻又把等待变成可见信息；
   同时在离开当前对局的入口（`setMode`）里统一取消，否则这条提示会跟着玩家飘到下一个界面。
41. **浏览器请求 ≠ Node 请求：Chrome 只认 Windows 系统代理**。这是 OpenAI 系地址"挂死"的根因
   （`api.openai.com` 直连**挂死 >9s**，走 `127.0.0.1:7897` 只需 **1.1s**），而你在设置里填的
   代理**根本没被浏览器用上**。**判据**：同一次请求，Node 侧 2 秒拿到真 401，浏览器侧 9 秒还没回。
   解法不是"把超时调长"，而是**换出网的人**：`vite` 同源中转 `/__aiaid/relay` 由 Node 代发，
   顺带把跨域预检也一并绕开。
   ★ 做这类"换个层发请求"的改动时，**别只测本机 happy path** —— 要拿**真实接口**验：
   `curl` 打中转 → 真实 DeepSeek 回真 401（0.26s）、经 Clash 隧道打 `api.openai.com` 回真 401（2.2s）。
   ⚠️ **但这条不能到处套**：它只解释"目标地址需要代理"的情形。**国内直连类接口（DeepSeek 等）
   本来就不靠代理** —— 2026-09-14 玩家追问"我配的是 DeepSeek"时实测：本机 Windows 系统代理
   是**关**的（`ProxyEnable=0`），浏览器直连 DeepSeek 的 **CORS 预检 200 / 0.26s、POST 401 / 0.12s**，
   走中转同样 401 —— **两条路都通**。所以"填了 DeepSeek 也超时"**不是网络问题**，而是下面第 45 条。
   **教训：拿到一个能解释现象的原因，也要先确认"这个原因对当前这个目标成不成立"**，
   否则会用一个正确的结论去答一个不适用的问题。
45. **"超时"要先分清两种：请求压根没到，还是响应头到了、body 还没到**。后者是
   **非流式 LLM 请求的常态** —— 网关（DeepSeek 用的就是 openresty）**立刻回 200 响应头**，
   正文要等模型把整段 JSON 生成完才吐。若代码把"`fetch` resolve"当成"请求结束"而在那时
   清掉超时（第 37 条的坑），`res.json()` 就永久挂起 —— 症状正是"一直问、没结果、再点只说取消了
   上一次"。**排查顺序**：先看 console 有没有 CORS / 网络错（请求压根没到）→ 都没有就怀疑
   "头到了 body 没到"。复现工具：`AID_STUB_DELAY_MS=4000`（先回头、4 秒后发 body），
   直连走 `_flow22.json`、中转走 `_flow23.json`；断言里用 **Resource Timing** 看请求 URL，
   确认测的确实是那条路径（别把中转的缓冲当成了直连的行为）。
   ★ 反过来也要守：修复是"超时**贯穿**读 body"，**不是"读到一半就放弃"** —— 所以单测里
   必须有一条"body 稍后才到 ⇒ 必须等到并成功"（`tests/run.ts` §19 ⑧）。只测"取消能打断"会
   把修复做过头，变成"稍慢就误判超时"。
46. **两条出网路径都要各验一次**。加了中转之后，"中转路径能过"不等于"直连路径也能过"，
   反之亦然：中转会**把整个响应缓冲**（`forward()` 在 `res.on("end")` 才 `resolve`），所以它
   **天然掩盖**"先回头后到 body"的问题，而直连不会。`_flow22`（`relay='off'` 直连）与
   `_flow23`（`relay='on'` 中转）**必须成对存在**，否则将来有人改坏其中一条，另一条照样绿。
42. **超时秒数、上游代理这类"环境相关量"必须是配置项，不能写死**。写死 30 秒对推理型模型
   （`deepseek-reasoner` 这类首字二三十秒的）就是"永远超时"。改完还要**让状态可查**：
   设置页直接写出「出网方式：本地中转 / 浏览器直连（自动探测，当前中转=开）」+ 超时秒数。
43. **先给"测试连接"，再谈排查**。玩家填错地址/Key/模型名时，唯一反馈是"点 → 等 60 秒 → 超时"，
   分不清哪一环错。`aiAidPing()`（`max_tokens: 4` 的最小请求）1 秒内就能把
   「4xx 详情 / 连不上 / 中转失败」摆出来 —— 一个按钮省掉整轮"改一处等一分钟"。
44. **按钮排布别只看代码，要看截图**。4 个键塞进 `.btn-row`（flex-wrap + `min-width: 76px`）时，
   长标签「本地中转：自动（现为开）」把整行挤成三行、文字互相叠 —— **功能全对、界面全烂**。
   截图之前，我以为这行没问题。改成两行两键 + 标签压到 5 字（`中转·自动`）、
   把"当前是否真的在走中转"挪进说明框就清爽了。

47. ★ **同一条规则在"两种模式"下可以是两个值 —— 别把其中一个写死**（2026-09-14 玩家实报
   "翻棋里第一排/最后一排和大本营的子走不动，原版可以"）。根因：`canActivate` 里写死了
   `if (isBase(from)) return false;`，而原版**走法生成是两套子系统**、由规则结构体偏移 +1 的
   字节二选一：**翻棋**（`Msg_Start_2`→`FUN_00068538` 洗牌）走 `FUN_0006919c`，**没有大本营
   这道门**；**布阵**（`Msg_Start_5`→`FUN_00069a74` 读 `.lay`）走 `FUN_0006a098`，门闸
   `(&DAT_00133cb4)[i]==0` 在 `{1,3,56,58}` 恒 1 ⇒ **整格跳过**。修成 `baseFrozenOf(opts)
   = !opts.flipMode` 后两条都对了。**教训**：逆向到"某规则"时先问一句"它是**模式的函数**
   还是常数"；两份模式专属规则文本（`rulelay.txt` vs `ruleflip.txt`）就是最好的对照表 ——
   一条只在其中一份里出现，几乎一定意味着它是**模式相关**的。
48. ★ **造验证局面时先看"这条规则在这个局面里有没有机会触发"**。验 #47 时第一版 UI 哨兵用
   `new FlipGame()`（**满盘 50 格全占**）造局面，4 个格子的落点全是 0 —— 一度以为没修好。
   其实**翻棋里大本营/行营都是安全岛**（`cmdSafe=true`）+ 邻居被己方/敌方占满 ⇒ 那枚子
   "吃不动（安全岛）、叠不上（己方）"，**落点真的是 0，这是对的**。改成**净空盘**后 4/4 通过。
   **教训**：一个"全 0 / 全失败"的断言，先怀疑**输入局面本身**，再怀疑被测代码。
49. ★ **"点了没反应"是最坏的交互 —— 规则对，也要把理由说出来**（2026-09-14 玩家实报
   「为什么地雷吃完了，不能吃军旗？」）。扛旗是**两道门的与**（对方地雷清零 **且** 兵种资格），
   但两道门**都不显示在盘面上**：旧版 `click()` 点敌旗只是 `return false`，玩家只能干瞪眼。
   更坑的是**规则文本自相矛盾**（见 §6 / SPEC §5.6）：`rulelay.txt` 写「任何棋子都能扛军旗」，
   可引擎实际要求"本方现存最弱的子"；`ruleflip.txt` 写「地雷和军旗只有工兵能吃」才跟引擎一致。
   ⇒ 凡是"玩家看得到操作入口、却看不到失败原因"的地方，都要有一条**解释通路**
   （这里就是 `core/rules.ts` 的 `flagCaptureHint`：先说兵种、再说雷数）。
   它的"够不够得着"用**替身盘面**判：把敌旗临时换成一枚工兵（全场最弱）再跑一次
   `legalTargets` —— 落得下去 ⇒ 纯属权限不够，值得解释；落不下去 ⇒ 是路太远，**别拿规则误导人**。
   同时别忘了暗棋的**信息公平**：敌旗没翻开时不许提示，否则等于替玩家认旗。

50. ★ **"轮到谁"别塞进同一个函数**（2026-09-15 做 AI 观战时踩的）。`aiTurn()` 里写死了
   `lay.turn !== AI_SIDE` / `flip.turn !== 1` —— 它服务的是"人执红、电脑执蓝"。
   观战要**两边都是 AI**，如果直接复用它，红方那半回合会被这两个门挡掉，
   表现是"红方思考中"永远不动，而且**不报错**。
   ⇒ 正确做法是在 `scheduleAi()` 里**先分流**到 `scheduleWatch()`，`aiTurn()` 一行都不动 ——
   那条路径已经验收过，改它等于同时动两个功能（本项目的回归常从这儿来）。

51. ★ **"看得见全部"和"知道全部"是两件事**。观战的上帝视角只许改**渲染**
   （`draw()` 里传 `revealAll`），`flip.opts` / `lay.opts` 一行都不能动。
   一旦给 AI 开了天眼，它下出来的就不是这套 AI 的棋 —— "学技法"这个目的直接落空。
   所以"暗棋观战"是**最值得看的一种局**：AI 靠推理（`buildBelief`），
   而你在上帝视角里能逐手对照"它猜的 vs 实际是什么"。

52. **原版 IconBtn 的标签区只放得下 4 个字**。☰ 菜单标签一旦超宽（"上帝视角·开" 6 字、
   "速度·极快" 5 字），文字会**溢出格子、压到相邻项上** —— 而且 **DOM 断言是绿的**
   （`textContent` 完整、格子数正确），**只有截图才看得出来**。
   ⇒ 菜单标签一律 ≤4 字，完整语义挪到 `status()` 里讲（"观战设置：上帝视角 · 速度快 · 红困难/蓝困难"）。
   同理：`WATCH_SPEEDS` 的 `name` 必须是单字，就是被这条逼出来的。

53. **`clickflow.mjs` 的 `probe` 必须自带 `return`**。它跑在 `(() => { … })()` 里，
   只写表达式（`JSON.stringify(x)`）会**静默返回 `null`** —— 报告里满屏 `→ null`，
   看起来像"页面全坏了"，其实只是忘了 `return`。同一趟里还顺手给 clickflow 加了
   `{"shot":"路径.png"}` 步骤：`shot.mjs` 只能"打开 URL 就拍"，拍不到**点完之后**的界面。
   ⚠️ **`clickXY` 恰好相反 —— 绝不能带 `return`**（2026-09-15 写翻棋悔棋 flow 时踩的）。
   `probe` 是语句体、要自己 `return`；而 `clickXY` 的字符串形态会被包成 `return (EXPR);`，
   只吃**裸表达式**。写成 `"clickXY": "return window.__junqi.cellCenter(0);"` ⇒ 展开成
   `return (return …;)` ⇒ `SyntaxError`，该步直接报"表达式没返回可用的 {x,y}"，
   **后面的点击全落空**，最后满屏"无棋可悔"的假阴性（看起来像功能坏了，其实一步没点中）。

54. ★ **异步的"轮次循环"必须自带重试，否则一丢就永久停摆**（2026-09-15 做云端执子时踩的）。
   观战的循环是 `scheduleWatch → watchStep → … → afterTurn → scheduleAi → scheduleWatch`。
   引擎手是同步的，`watchStep` 一进去就把这手走完；**云端手是异步的**，`watchBusy` 会在一整趟
   网络往返里为真。于是出现这个窗口：用户在"云端思考中"按了「继续」→ `scheduleWatch` 排的定时器
   到点时 `watchBusy` 仍是 true → `watchStep` 直接 `return` → **再没人排下一手**，
   观战从此永远停在原地（表面症状是"一直在思考"）。
   ⇒ `scheduleWatch` 的定时器回调里遇到 `watchBusy` 要**晚 200ms 再排一次**，不能直接丢掉。
   同理 `watchStepOnce` 遇到 `watchBusy` 要明确说"云端正在思考，稍等一下…"，而不是默默什么都不做。

55. ★ **在途的异步请求必须在"离开现场"时作废**。观战里换了玩法、退回首页、
   重开一局，都会让上一局那个还在飞的云端响应变得**有害** —— 它一旦落地就会把一手棋
   写进**新**盘面（`lay.click()` 不关心 mode 是不是已经变成 `home`）。
   ⇒ `watchAbort.abort()` 要在 `stopWatch()` **和** `enterWatch()` 里都调，
   并且 await 之后第一件事就是查 `!watchOn || signal.aborted` 然后 **直接 return**。
   验收方式：桩故意拖 2500ms 才回 body，在这个窗口里点退出，断言"退出前 plies == 退出后 plies"。

56. **"云端手"和"引擎手"能报的信息不可互换**。引擎手能报 `深度 / 节点数`，
   云端手这两项**根本没有** —— `AI_STATS` 里留着的是**上一次引擎搜索**的残留值，
   直接报出去就是**假数据**。⇒ `recordWatchPly` 收到 `cloud:true` 时把 depth/nodes 整块置 0，
   改报"云端决策 xx ms + 模型给的理由"。界面上一律按 `p.cloud` 分叉，不要试图统一成一种格式。

57. **同一个 enum 收窄会让"必然会变回来的判断"编译不过**。自检里写了
   `watchKind[0] = "cloud"; await watchCloudStep(0); … watchKind[0] === "engine"` ——
   TS 只看赋值就把类型收窄成字面量 `"cloud"`，于是判它"永假"而报 TS2367。
   `const x: T = watchKind[0]` **也不行**（初值仍被收窄）。要 `watchKind[0] as WatchAgentKind`
   断言回宽类型；或者干脆用一个函数读回来。
   ⚠️ 同一个坑还有 `boolean` 版：`watchPaused = false; scheduleWatch(); watchPaused === true`
   —— TS **把窄化带过了函数调用**（它假定 `scheduleWatch` 不会改外部变量），照样报 TS2367。
   ⇒ 写成 `const pausedAfter: boolean = watchPaused;` 再比。

58. ★★ **同一文件的多处修改必须串行，绝不能放进同一条消息里并行发**（2026-09-15 踩了 5 次）。
   并行发出的两个 `Edit` 都对着**同一份**文件快照做匹配，后落盘的那次会把前一次的改动**抹掉**，
   而两次调用**都返回 "Successfully updated"** —— 于是代码看起来改完了，实际少一块，
   只有 `tsc`/probe 报出来的错才暴露（`aiRootOrder` 没导出来、`brief: extra?.brief` 丢了、
   `watchTogglePause` 里的逐手分支整个不见）。
   ⇒ 铁律：**一次一个 Edit，改完再发下一个**；改完用 `grep` 复核关键符号是否都在。
   跨文件的并行没问题（各改各的），危险的是**同文件**。

59. ★ **"展示了什么"和"它其实按什么排的"必须对齐，否则等于给 AI 抹黑**。学习面板第一版
   只按「走后局面分」列候选、只报一个名次 —— 于是几乎每一手都显示"实际走的是第 5 名（分最低）"，
   看着像 AI 乱走。真相是引擎根排序**吃子一律 `+100000`**，而吃子那手的静态局面分常常偏低。
   ⇒ 面板现在**两个顺位都报**（"搜索前第 1 顺位 · 走后局面分第 5 名"）。
   凡是"给人看的排序 + 机器内部另有排序"的地方，都要检查这一点。
   （另：分数的量级也不能混用 —— `aiRootOrder` 的 `100000` 只对**同一手内**可比，
   跨手/给读者看必须换成 `evalForSide`。）

60. **"挂在棋盘外侧"的面板，可用宽度要自己算**。`#app` 的宽度就是**棋盘宽**
   （`resize()` 按等比缩放写死），所以单侧留白 = `(视口宽 − #app 宽) / 2`。
   学习面板据此决定宽度与显隐：`< 168px` 直接收起（宁可没面板，也不能糊在棋子上）。
   ⚠️ 无头验收时别用默认的 900×1600（那是手机竖屏，留白为 0 ⇒ 面板必然 hidden）——
   `clickflow.mjs` 要 `DOM_W=1400 DOM_H=900` 才验得到面板本体。

61. ★★ **"可选"的功能，如果两个选项在屏幕上长得一模一样，等于没做**（2026-09-15）。
   用户要"AI 观战能选明棋/暗棋"，第一版只把 `watchReveal` 接到**规则层**
   （明棋 AI 全知 / 暗棋 AI 靠推理），但**上帝视角 `watchGod` 缺省是 `true`** ——
   `draw()` 里 `revealAll: (watchOn && watchGod) || lay.revealAll` 一强制全亮，
   两种模式画出来**完全一样**，用户当然回一句"我想看暗棋，但现在还是明棋"。
   ⇒ `enterWatch()` 里 `watchGod = watchReveal`：**选暗棋就把观者按回对局视角**，
   要看全貌自己去 ☰ 点「视角·开」。
   教训：**新增一个"模式/开关"时，先问"用户凭什么看出它生效了"**，
   并且把这条差别**写进自检的断言**（本项：`缺省暗棋=是(观者视角=对局)` +
   `board.revealed=0`，即 50 枚真的全盖着）。

62. ✏️ **对话框的值文案有硬性宽度上限，超了会被"静默裁掉两端"**（2026-09-15）。
   `dialogRow()` 把文字画进 **固定 300 设计 px 宽**的 canvas（原版 XML
   `Button rect="330,…,630,…"`），所以**不是溢出、不是换行，是两端各切掉一截** ——
   截图看上去像"文字跑出按钮"，很容易误判成布局塌了。
   实测：`暗棋（AI 靠推理）` = **366px**（两端各丢 33px）、`明棋（AI 全知）` = 321px；
   45px 字号（`DLG_TEXT_SIZE`）下一行最多约 6 个全角字。
   ⇒ 现文案 `明棋：全知`(225px) / `暗棋：靠推理`(270px)。
   **别再靠肉眼估**：新文案先在页面里量一遍 ——
   `canvas.getContext('2d').font='45px ZYKai'; measureText(文案).width`，
   或直接跑 `tools/_audit/_dlgprobe.json`（量每行按钮/位图矩形与候选文案宽度）。
   回归哨兵：probe 第 ⑯ 项 H 段读每行位图的 `alt`（**存着未裁的原文**）重量宽度，
   超 300 即报"开局框文案装得下=否"。

63. **观战"防磨棋"要两层，缺一层都不好用**（2026-09-15）。两台同水平 AI 最爱在两三个格
   之间无限来回，子力毫无变化 —— 只靠原版的"连续 70 步无吃子"要磨很久，观战看着像死机。
   ⇒ **事前**：`watchSeen`（局面指纹→次数）+ `watchAvoid()` 算出"走完会回到旧局面"的着法，
   `applyAvoidBias` 把它们**沉到队尾**（**只降权、不剔除** —— 剔了可能误判"无子可动"）；
   **事后**：`session` 侧 `DRAW_REPETITION = 3`，同一局面第 3 次出现即判和。
   只引导不判和 ⇒ 万一它宁愿被降权也要走回去，永远卡着；只判和不引导 ⇒ 干等 70 步。
   ⚠️ `repeatDraw` **必须默认关**（人机/双人对局保持原版行为，原版没这条规则），
   只有 `enterWatch()` 会 `setRepeatDraw(3)`；单测 15b 用 `repeatDraw=0` 跑到 3 次重复仍**不判和**。
   ⚠️ 自检里用 `lay.click` **手工**构造循环局面时，得自己补 `watchNotePos()` ——
   `watchSeen` 只在 `watchEngineStep` 里更新，不补就查不到旧局面（规避数恒为 0，假阴性）。
   ⚠️ "原路返回"要求落点是**相邻空格且不是大本营**：进了大本营的子按规则不能再动，
   返回不合法，循环局面根本构造不出来。
64. **"选项只写当前值" = 用户认为它不存在**（2026-09-15）。观战开局框的「玩法」行原本是
   `value: watchVariant === "flip" ? "翻棋" : "布局"` —— 逻辑没错（点一下就切），
   但用户打开框**只看到「布局」两个字**，整屏找不到"翻棋"，于是反馈「**AI 对战增加翻棋**」
   （他判定这个功能压根没做，其实翻棋一直都在）。
   ⇒ 值要**把两个选项都写出来**、并让点击结果可预期：`布局 → 翻棋` / `翻棋 → 布局`
   （读作"现在是 A，点一下变 B"，实测 ~250px，仍在 300px 硬上限内；`→` 走的是 canvas 字体
   渲染而非原版点阵字库，实拍确认字形正常、不是豆腐块）。
   ⚠️ 同理：翻棋下「明暗棋」那一行**不许整行消失** —— 那是"翻棋没有视角可选"，不是
   "翻棋不需要"（翻棋规则层恒为暗，这一行只决定观者看到什么，见 §10.2.3）。
   两条都进了 probe 哨兵，并**按铁律反向验证**过确实会报错。
65. **Node 19 起 `globalAgent` 默认开着 keep-alive ⇒ "复用池里那条半开连接"就是
   `read ECONNRESET` 的经典来源**（2026-09-15，玩家实报观战**第 1 手**就停：
   `蓝方（云端）这一手失败：中转失败：read ECONNRESET`）。
   实测（本机假上游，响应后 1.2s 掐掉空闲连接）：
   ```
   默认 agent   → reused=true   ← 复用池里的旧 socket
   agent: false → reused=false  ← 每次新建
   ```
   观战把这个坑放大到近乎必现：一手云端棋走完，界面要**停 2.6 秒甚至几十秒**才发下一手，
   正好落在"上游回收空闲连接"的窗口里。第 1 手中招是因为玩家多半先点过「测试连接」探路，
   那发请求留下的 socket 进了池子，等正式开局早就失效了。
   ⇒ 中转**不复用连接**：`agent: false` + 请求头 `Connection: close`。
   ⚠️ 两道保险**各自都够**（反证过：只留任一层都不复用，两个都去掉才会复用），
   所以哨兵要断言的是"**两发落在不同的上游远端端口**"这个**性质**，而不是某一层的实现
   —— 我曾以为"把 agent 改回去哨兵会红"，结果它照样绿，查下去才发现真正挡住复用是另一个头。
   ⚠️ 隧道那条路（`createConnection` 外部塞 socket）**不设 agent**，别两种接管方式一起上。
66. **两层重试会互相抵消：把"已重试 N 次"当**终态**，等于"看着在容错、其实一层都没生效"**
   （2026-09-15，本轮最值钱的一次翻车）。加完重试后我写了个哨兵测试想证明
   "观战那层也会重试"，结果**关掉观战重试它照样能恢复** —— 说明救回来的是别的东西。
   连着查出两个洞：
   - ① `isTransientNetError` 把 `已重试 3 次` 归为"终态"。本意是防叠加（3×2×2=12 次），
     实际把**上层唯一能用的补救时机**也一起否决了 —— 中转那 ~0.7 秒三次打完就再没机会。
     ⇒ **"要不要再试一次"是时间尺度问题**（马上再打 vs 隔 1.5 秒再打），不是错误性质问题；
     判定表**只判性质**，叠加控制交给调用方按**结构化信号**做：页面读 `x-aiaid-attempts` 头。
   - ② 那个头**只在成功路径回了**，失败路径（恰恰最需要它）漏了 —— 于是页面看不到
     "中转已重试 3 次"，自己又叠一层。⇒ 用一个 `RelayUpstreamError` 带上 `attempts`，
     失败响应也带头。
   ⇒ 最终三层各管一段：**中转** 3 次（~0.7s 内换新连接）｜**页面**再 1 次（+0.35s，
   仅当中转没重试过）｜**观战**再 1 轮（+1.5s，只要性质是瞬态）。上限 9 次但每次都是
   毫秒级快速失败，总时长仍受那 60 秒单预算约束。
   ⚠️ 验它只能靠**端到端**（`_watchcloud.mjs RST_FIRST=4`）：单测里 `fetch` 是假的，
   看不出"到底谁在重试"。反证：把 `CLOUD_TRY_ROUNDS` 改回 1 ⇒ 0 手停住、8 条 ✗。
67. ★★ **"连不上上游"这五个字底下压着至少五种病，报错不可行动 = 玩家只能瞎试**
   （2026-09-15，玩家第二次实报「应该还是不能用啊，一直提示连接不上上游」）。
   上一轮（踩坑 66）加了三层重试，玩家反馈**毫无变化** —— 因为根因根本不是"重试不够"：
   `DNS 写错 / 端口不通 / 这个地址在当前网络下必须走代理 / 玩家填的「上游代理」本身没开 /
   其实通了、只是 Key 或模型名错`，**这五种在界面上长得一模一样**。玩家分不出是哪一种，
   于是判定"这个功能就是坏的"。四次改动，每条都对着一种病：
   - ① **连接阶段单独计时**：`CONNECT_TIMEOUT_MS`（默认 8s，`AID_CONNECT_TIMEOUT_MS` 可覆盖）
     量 DNS+TCP+TLS，连不上就**立刻点名 host**（`连不上上游 api.openai.com:443：…`），
     不再伪装成"上游 60 秒没回应"（后者会让玩家以为模型慢，把排查带偏）。
     ⚠️ `TLSSocket` **在 TCP 刚连上时也会发 `connect`**（TLS 还没握完）⇒ https 必须只认
     `secureConnect`、http 才认 `connect`，靠 `s.encrypted` 区分。**两个都监听 = 秒表被提前
     清掉 = "握手卡死"漏成"上游超时"**（回归哨兵 ⑪ 当场抓到，监控卡 16s）。
   - ② **直连不通自动借本机代理**：探测 7897/7890/10809/10808/1080/8889，通了就用它重打一发。
     解决"玩家根本不知道要填代理"（`netprobe.mjs` 实测：`api.openai.com` 直连 TCP 超时、
     经 7897 通）。⚠️ **本机地址除外**（`isLoopbackHost`：`127.0.0.1`/`localhost`/`::1`）——
     那是"服务没起"不是"被墙"，借代理只会把 `ECONNREFUSED` 糊成代理的 502。
   - ③ **借了代理要如实说**：中转回 `x-aiaid-proxy-used` 头，UI 才敢写"已自动走本机代理 X"。
   - ④ **`GET /__aiaid/diag` 诊断端点 + 设置面板「诊断出网」按钮**：Node 侧逐段量
     DNS→TCP→HTTPS→代理，回一句**结论**（`verdict`）。这是给玩家的"自救入口"——
     点一下就告诉他到底哪一段断了、该改哪一格。
   ⚠️ 顺带修：上游网关的 502 曾被页面一律报成「中转失败」，害玩家去查本地中转。
     ⇒ 中继自己的 502 才带 `x-aiaid-origin: relay`，页面据此区分。
   ⚠️ diag 路由**必须写在 RELAY 过滤之前**（否则被 `next()` 掉，返回 404/空体）。
   ⚠️ 测试要**隔离环境**：脚本里 `setLocalProxyCandidates([])` / `AID_LOCAL_PROXIES=`
     关掉自动借代理，否则开发机开着 Clash 会让结果随环境漂移（中继测试桩都在 127.0.0.1，
      靠 `isLoopbackHost` 天然排除）。
   ✅ 端到端实测（`_flow37.json` 真实点击）：① `api.openai.com` + 没填代理 ⇒ 自动借 7897
     拿真 401（`x-aiaid-proxy-used: http://127.0.0.1:7897`、`x-aiaid-attempts: 2`）；
     ② `127.0.0.1:9377` 没监听 ⇒ 502 带 `连不上上游 127.0.0.1:9377：connect ECONNREFUSED`
     （经 Clash 也没被借代理）；③ 面板点「诊断出网」⇒ hint-box 出现
     `✓ DNS / ✓ TCP / ✓ HTTP 401 / 本机探到 7897 / → 结论`。
68. ★★ **"翻棋不支持悔棋"是没核对原版的臆断，删了**（2026-09-15，玩家直接质疑
   「为什么翻棋不支持悔棋？你研究透 APK 没有？它是支持的」—— 玩家是对的）。
   `doUndo()` 的 flip 分支原先写死 `status("翻棋不支持悔棋")`，**从未在真机上验过**。
   两条证据推翻它：
   - **静态**：`libjunqi.so` 里有**一等公民**的悔棋事件族 —— `Junqi.RegretReq /
     RegretAgree / RegretDisagree / RegretSend / RegretConfirm / RegretFail`
     （还得联网时走 Req/Agree 的协商，单机直接本地生效）。悔棋是原版的**正式功能**，
     不是布局模式独有。
   - **动态**：雷电 9 跑原版 ⇒ 翻棋开局（全绿背）→ 翻开一枚 → ☰ →「悔棋」⇒
     那枚**原样盖回**，与全新棋盘**像素差分 0px**；再翻两枚后悔一次 ⇒ **只盖回第二枚**
     （=`退一手` 语义，不是"重开"）。实拍证据 `tools/_emu/_undo_*.png`。
   ⇒ 复刻侧把 `FlipGame` 与 `LayGame` **同构**：加 `history: FlipSnapshot[]`、
   `canUndo()`、`undo()`。⚠️ **快照必须带上翻棋特有字段**（`turn` 存 0/1 座位、
   `sides`、`revealedColors`、`winner/winnerReason`）—— 翻棋颜色在首翻前未定，
   退掉**定色那一手**时得把"谁执红"一起回滚，只还原 `type/owner/revealed` 会留下
   一个"已定色但没有已翻子"的脏状态。入栈位置也有讲究：`reveal()` 里要写在
   **三个守卫（over/empty/revealed）之后**，否则点空/点已翻的无效点击会污染历史栈。
   ✅ 端到端实测（`tools/_audit/_flow38.json` 真实鼠标 12 步）：翻开①`revealed 0→1`
   `canUndo→true`、翻开②`1→2`、点浮动悔棋键`2→1`（**只退一手**）、☰→「悔棋」`1→0`
   `canUndo→false`、再点 ⇒「没有可悔的棋」。全部与预期逐项吻合。
69. **原版翻棋盘上那枚蓝色箭头浮动图标 = "返回主菜单"，不是"悔棋"**（2026-09-15 顺带发现）。
   实测原版（布局 / 翻棋皆然）右侧那枚 `icon_next.png`（蓝箭头）点下去是**退出对局回主菜单**，
