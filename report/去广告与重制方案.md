# 军棋 APK 去广告 / 重制 可行性方案

> 基于 `com.cnvcs.junqi` v1.58 完整逆向产物（Java + Smali + Native + 资源四层全还原）

---

## 一、结论速览

| 目标 | 可行性 | 说明 |
|---|---|---|
| 去掉广点通广告 | **可行** | 必须用「桩替换」，不能直接删 SDK（原因见第三节） |
| 换图标 / 换名 / 换文案（换皮） | **可行** | 需补一个 SPAK 打包器；资源已 100% 解出 |

| 从零重写一个完整可玩军棋 | **可行但工作量大** | 棋盘/规则/关卡可复用，**AI（人机）是硬骨头** |

## 二、广告注入机制（已完整逆向）

这个游戏的 Java 层是个**纯空壳**（`App.java` 里一行广告代码都没有），广告完全由 **native 层驱动**：

```
游戏脚本层触发事件
      │
      ▼
libjunqi.so
  ├─ FUN_00073818  ── 初始化
  │     FindClass("com/qq/e/comm/managers/GDTADManager")
  │     GetStaticMethodID("getInstance", "()Lcom/qq/e/comm/managers/GDTADManager;")
  │     GetMethodID("initWith", "(Landroid/content/Context;Ljava/lang/String;)Z")
  │
  ├─ FUN_000738e4  ── 横幅广告
  │     FindClass("com/cnvcs/AdLisG")            → NewObject（监听器）
  │     FindClass("com/qq/e/ads/banner2/UnifiedBannerView")
  │     GetMethodID("<init>", "(Landroid/app/Activity;Ljava/lang/String;Lcom/qq/e/ads/banner2/UnifiedBannerADListener;)V")
  │     NewObject → NewGlobalRef → 存入对象偏移 +8
  │     GetMethodID("setRefresh", "(I)V")  → CallVoidMethod
  │     GetMethodID("loadAD", "()V")       → CallVoidMethod
  │
  └─ FUN_00073a8c  ── 开屏广告
        FindClass("com/cnvcs/AdLisGs")           → NewObject（监听器）
        FindClass("com/qq/e/ads/splash/SplashAD")
        GetMethodID("<init>", "(Landroid/content/Context;Ljava/lang/String;Lcom/qq/e/ads/splash/SplashADListener;I)V")
        NewObject → NewGlobalRef → 存入对象偏移 +4
        GetMethodID("fetchAndShowIn", "(Landroid/view/ViewGroup;)V") → CallVoidMethod
```

**配置来源**：native 从配置对象读取键 `app`（appId）与 `id`（广告位 ID），并读 `interval` / `delay` 控制刷新与延迟。已提取到广点通 appId：**1110512615**。

**回调回传链**：SDK 播放 → `AdLisG` / `AdLisGs` 回调 → `App.OnEvent("splash"|"banner", "dismiss"|"close"|...)` → native 继续游戏流程。

## 三、为什么不能「直接删掉 com.qq.e」

**已确认：native 的 JNI 包装层完全没有异常检查。**

`FUN_00072628`、`FUN_000725f0` 都是裸的 tail call 转发到 `JNIEnv` 函数表，没有任何 `ExceptionCheck` / `ExceptionClear`：

```c
void FUN_00072628(int *env) {
    (**(code **)(*env + 0x84))();   /* GetMethodID — 无异常检查 */
}
void FUN_000725f0(int *env, ...) {
    (**(code **)(*env + 0x74))(...); /* NewObject — 无异常检查 */
}
```

同时 `FUN_000738e4` / `FUN_00073a8c` 里对 `FindClass` 的返回值**只做 `DeleteLocalRef` 判空，不做异常清理**。

**后果**：删掉 `com/qq/e/**` 后 → `FindClass` 返回 NULL → `GetMethodID(NULL, ...)` 抛出 `NoClassDefFoundError` → 该 pending exception **无人清理** → 之后**所有** JNI 调用（包含游戏本体的）全部失败或直接 abort → **必然崩溃**。

**结论：必须在 Java 侧保留同名同签名的类，让 JNI 调用全部成功。** 这就是「桩替换」。

## 四、路线对比

### 路线 A：桩替换去广告（推荐）

保留全部 `com/qq/e/**` 的**类名与方法签名**，把实现换成空壳；其余 SDK 文件与 Manifest 组件删除。

| 处理 | 类 | 要点 |
|---|---|---|
| 保留原样 | `com/qq/e/ads/banner2/UnifiedBannerADListener`（接口） | AdLisG 需要 implements |
| 保留原样 | `com/qq/e/ads/splash/SplashADListener`（接口） | AdLisGs 需要 implements |
| 保留原样 | `com/qq/e/comm/util/AdError` | 回调参数类型 |
| 保留原样 | `com/cnvcs/AdLisG`、`com/cnvcs/AdLisGs` | 回调转发，不含广告逻辑 |
| **改写为桩** | `com/qq/e/ads/banner2/UnifiedBannerView` | 继承 **FrameLayout**（native 会调 `addView`/`removeView`）；构造 3 参；`setRefresh(I)V`、`loadAD()V` 空实现 |
| **改写为桩** | `com/qq/e/ads/splash/SplashAD` | 构造 4 参；`fetchAndShowIn(Landroid/view/ViewGroup;)V` **必须立即回调 `listener.onADDismissed()`**，否则闪屏永不消失 |
| **改写为桩** | `com/qq/e/comm/managers/GDTADManager` | 静态 `getInstance()` 返回实例；`initWith(Context,String)Z` 返回 true |
| 删除 | `com/qq/e/**` 其余 ~230 个 smali | 含 ads/adn/comm 等 |
| 删除 | Manifest 中 GDT 组件 | `GDTFileProvider` / `DownloadService` / `ADActivity` / `PortraitADActivity` / `LandscapeADActivity` / `Rewardvideo*ADActivity` |

**优点**：native 零改动；JNI 全部命中；闪屏可做到「秒过」（桩内立刻发 dismiss）。
**风险**：低。唯一需验证的是 `UnifiedBannerView` 被 `addView` 进界面的位置与后续 `removeView` / `setVisibility` 调用。

---

### 路线 B：Patch native 跳过广告创建

把 `FUN_000738e4`（偏移 `0x738e4`）与 `FUN_00073a8c`（偏移 `0x73a8c`）入口改写为：

```asm
mov r0, #0      ; 00 00 A0 E3
bx  lr          ; 1E FF 2F E1
```

**可行性存疑**：
- 两函数 `callers=0`，说明是**经函数指针表间接调用**（脚本驱动的 UI 架构），patch 后不会破坏直接调用链。
- **但返回 0 的语义未验证**：`fetchAndShowIn` 从不被调用 → 闪屏 View 可能从未加入 → 游戏可能直接卡在启动流程等待 `"splash"/"dismiss"` 事件。
- 需动态验证调用方对返回值的分支处理。

**结论**：作为路线 A 的备选或补充，不建议单独使用。

---

### 路线 C：换皮 / 魔改（做一份「自己的版本」）

在路线 A 基础上追加：

1. **补 SPAK 打包器** —— 密钥已知（`c2cbe5e7…d523`），算法为 XOR-32 + zlib，可逆向写出 packer，把改过的资源重新塞回 `.pak`。
2. **替换视觉资源** —— 690 个资源已全解出，其中 339 XML / 196 PNG / 18 WAV / 10 JPG / 51 `.lay` 关卡 / 24 `.cfg`。
3. **改关卡** —— `data/lay/*.lay` 已恢复真名，直接编辑。
4. **改文案** —— `data/config/string.xml` 可直接改中文。
5. **改品牌** —— 包名、应用名、图标、`base.cfg` 里的 `siteUrl` / `serverHost` 等。

**注意**：`datah` / `datax` 两组资源名仍为 `<md5>.<ext>`，改包时**保持原文件名不变**即可（内容改了不影响键）。

---

### 路线 D：从零重写一个军棋游戏

不依赖原 native，用逆向得到的**规则知识**重写。

| 可复用 | 需重写 |
|---|---|
| 51 个 `.lay` 关卡（已解出） | 棋盘渲染与交互 |
| 棋子等级规则（司令 > 军长 > 师长 > 旅长 > 团长 > 营长 > 连长 > 排长 > 工兵；炸弹、地雷、军旗） | 走子合法性判定 |
| 布局模板（`data/config/*.xml`） | 暗棋翻开逻辑 |
| 图片/音效（版权受限，不适合分发） | **AI 决策（最难）** |

**技术栈建议**：HTML5 + Canvas/TypeScript（网页版，跨端好分发）或 Python + Pygame。
**工程量参考**：基本规则 + 双人本地对战 → 小；可用的电脑 AI → 大（原 native 的 AI 是 6158 个函数里的核心资产，无法直接移植）。

## 五、推荐路径

```
第一步：路线 A（桩替换去广告）        ← 立即可做，验证重打包链路是否跑通
   │
   ↓ 跑通后
第二步：路线 C（换皮）               ← 需先补 SPAK 打包器
   │
   ↓ 若想完全自主
第三步：路线 D（从零重写）            ← 与 A/C 并行，互不依赖
```

**第一步必须先做**，因为它同时验证了「smali 修改 → apktool 重打包 → 签名 → 安装运行」这条链路。链路不通，后面都免谈。

## 七、合规提示

修改自用 / 学习研究无碍。但需注意：

- **不可对外分发**：游戏本体著作权属 cnvcs，重打包分发构成侵权。
- **不可保留原广告位**：广点通 appId `1110512615` 属他人账户，移除广告是唯一合规做法（保留或替换=盗用广告位）。
- **`base.cfg` 内含他人服务器地址与 X.509 证书**，改包时应一并清理，避免误连他方服务器。
